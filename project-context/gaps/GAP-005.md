# GAP-005 - Immutable ReviewEvent Rules Are Weaker Than Domain Validation

Status: OPEN

Date: 2026-09-26

Source: `DISC-002`, finding `MSR-02`

Severity: High

## Observation

Firestore ReviewEvent create rules do not currently enforce the full application-domain contract.

The application domain validates stronger constraints including:

- rating/card-type enum values;
- scheduler metadata structure;
- numeric bounds;
- schema/version expectations;
- objective-correctness invariants.

Current rule coverage verifies ownership, required/extra fields, document identity, and immutability, but does not establish domain-equivalent content validation.

## Why this matters

An older, buggy, or directly scripted authenticated owner client can create malformed immutable ReviewEvent evidence.

Because ReviewEvents are append-only, malformed records cannot subsequently be repaired through normal update/delete operations.

Reconciliation can fail closed when encountering evidence the application schema rejects.

## Required handling

A future bounded work item should:

- bring Firestore ReviewEvent create rules into feasible parity with the domain schema;
- add emulator tests for valid and invalid enum values;
- validate scheduler metadata and numeric bounds where rules-language constraints permit;
- enforce schema/version and objective-correctness/card-type consistency;
- preserve owner isolation and append-only immutability;
- verify normal application and restore-created ReviewEvents continue to pass.
